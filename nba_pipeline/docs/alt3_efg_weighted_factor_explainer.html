Start with the possession. Then decompose the scoreboard.

This is the clean explanation for a brilliant intern: RAPM is not a box-score allocation system. It is a lineup-adjusted model of team outcomes. The Alt3 EFG-value bundle keeps that RAPM core, then replaces one opaque scoring target with a set of first-chance, free-throw, turnover, shot-location, and second-chance targets that can be audited back to row-level identities.

One row, ten players, one target. Change the target and rerun the same lineup logic. That is how a black-box scoring RAPM becomes a component map.

The context

Standard six-factor RAPM organizes player impact through shooting, turnovers, and rebounding on both offense and defense. Alt3 EFG-value is a parallel clean offensive scoring decomposition built because the ordinary TS/TOV split mixes shot-scoped and possession-scoped ideas.

The problem

A player can help scoring by creating rim attempts, making threes, avoiding first-chance turnovers, drawing useful free throws, sustaining second chances, or simply bending the geometry of the possession. A single off number knows the outcome but hides the mechanism.

The answer

Keep the RAPM machinery. Build cleaner scoring targets. Prove the row algebra before interpreting player coefficients. Then publish a weighted-factor file where the pieces tell a basketball story and still add back to total impact.

The active family

Use weighted_factors_alt3_efg_value_*. The older weighted_factors_alt3_* family is legacy/audit context and should not be used as the current public interpretation path.

The identities

These are the propositions the intern should be able to recite and audit. If the row-level math fails, the player-level interpretation is premature.

RAPM scoring layer = FIRST_CHANCE + SECOND_CHANCE_CLEAN
FC = ALT_EFG_VALUE + ALT_FT + ALT_TOV_VALUE
ALT_EFG_VALUE = ALT_EFG_BASELINE + ALT_EFG_ATOMS_VALUE

Atomic shot value

ALT_EFG_ATOMS_VALUE =
  ALT_EFG_RIM_FREQ + ALT_EFG_RIM_FG
+ ALT_EFG_MID_FREQ + ALT_EFG_MID_FG
+ ALT_EFG_THREE_FREQ + ALT_EFG_THREE_FG

Free throws

ALT_FT = ALT_FT_FREQ + ALT_FT_SEVERITY

Frequency prices each first-chance FT trip at the loaded-sample average trip value. Severity is what remains: trip type mix plus FT shooting.

Turnovers

ALT_TOV_VALUE = ALT_BADPASS_TOV_VALUE + ALT_SCORING_TOV_VALUE

This is point-valued, not the old rate-style ALT_TOV. True first-chance turnover rows get the average non-turnover first-chance scoring value as a loss.

The first-chance turnover guard

A row is a true first-chance turnover only if there was no prior first-chance FGA or FT completion in the same possession. If the possession already created first-chance scoring, the later terminal turnover does not also become the first-chance TOV bucket.

The ridge matrix

Every component is solved as a RAPM problem. That is the important engineering choice: we are not assigning a player his box-score events. We are estimating how lineups with him change the target.

The same lineup row can be solved once with ALT_FT, once with ALT_TOV_VALUE, once with ALT_EFG_RIM_FREQ, and so on. The matrix is the common measuring device. The target changes.

The objective

min || W^(1/2) (y - X_off beta_off - X_def beta_def) ||^2
  + alpha_off || beta_off - prior_off ||^2
  + alpha_def || beta_def - prior_def ||^2

Pure solves shrink toward zero. True-prior solves shrink toward priors. Offense and defense can have different alphas because their signal and noise are not the same. The public file sign-flips defense so positive defensive columns mean good defense.

Why reuse the matrix?

If the only thing changing is y, component differences are interpretable as different answers to the same lineup question.

Why coefficient sums can drift

Separate ridge solves, centering, time weights, and rounded exports can leave tiny coefficient gaps even when the processed-row algebra is exact.

The design decisions

The bundle is opinionated. These choices are what make it readable and less likely to collapse into a noisy pile of columns.

  • Use a shared first-chance denominator. Shot value, FT value, and turnover loss live on the same first-chance possession universe.
  • Use point-valued turnovers for the public additive layer. ALT_TOV_VALUE is a scoring complement; old rate-style ALT_TOV is useful but not the displayed parent.
  • Use six atomic shot pieces. Rim, mid, and three each split into frequency value and within-zone make value.
  • Keep broad zone solves as audit-only. Public rim/mid/three totals are derived from the frequency and FG atoms.
  • Display direct second chance. oSC and dSC come from SECOND_CHANCE_CLEAN, not from a residual.
  • Let ALT_EFG_BASELINE close the display. It is a replacement-shot / balancing bucket, not an observed shot-location skill.
  • Do not add assist drilldowns to the display sum. ASSIST_POINTS and RIM_ASSIST are supporting RAPM diagnostics, not additive children.

The goal and the hope

The goal is not to prove that we have isolated the soul of a player. The goal is to make a lineup impact number speak in basketball mechanisms.

The sentence we want

Instead of saying "this player is +4," we want to say: his lineups are +4 because they create rim value, avoid first-chance turnover loss, generate useful free throws, survive the second-chance layer, and leave only a small residual after assembly.

The intern's test

For any new component, ask four questions: What is the row target? What parent identity does it obey? What ridge matrix and alpha did we use? What sign convention will the user see?

The final rule

A good decomposition makes the scoreboard less mysterious without pretending basketball is less complex than it is.
