# Friend PBP Ingest Validation

## Purpose

Validate a third-party team-season play-by-play parquet against the repo's current raw
PBP contract before using that schema for pre-2014 ingest.

Current fixture:

- Friend source: `nba_pipeline/raw_data/BKN_2020_rs.parquet`
- Official reference: `nba_pipeline/raw_data/NBA20.parquet`
- Official BKN subset generated by harness: `nba_pipeline/raw_data/BKN_2020_rs_ours.parquet`
- Validation root: `nba_pipeline/validation/friend_ingest/`

## Harness

Run from the repo root:

```bash
python nba_pipeline/scripts/validate_friend_pbp_ingest.py
python nba_pipeline/scripts/analyze_friend_pbp_diffs.py
```

The harness:

1. selects the same 72 Brooklyn regular-season games from `NBA20.parquet`;
2. converts the friend schema into the repo raw contract;
3. writes side-by-side processed metric parquets under `validation/friend_ingest/processed/`;
4. runs small RAPM solves for `RAPM`, `TS`, `TOV`, and `REB` under `validation/friend_ingest/results/`;
5. writes `validation/friend_ingest/validation_report.json`.

The diff analyzer writes:

- `validation/friend_ingest/diffs/difference_summary.json`
- per-metric `*_official_unmatched_rows.csv`
- per-metric `*_friend_unmatched_rows.csv`
- `rapm_lineup_mismatches.csv`
- raw event coverage files: `raw_official_only_events.csv`, `raw_friend_only_events.csv`

It intentionally does not overwrite `nba_pipeline/processed/` or `nba_pipeline/results/`.

To test the partial-lineup RAPM path at full row weight:

```bash
python nba_pipeline/scripts/validate_friend_pbp_ingest.py \
  --allow-partial-lineups \
  --output-root nba_pipeline/validation/friend_ingest_original_partial_fullweight
python nba_pipeline/scripts/analyze_friend_pbp_diffs.py \
  --validation-root nba_pipeline/validation/friend_ingest_original_partial_fullweight
```

This mode preserves missing lineup slots as `0`, keeps rows with at least four known
offensive players and four known defensive players, and gives the row full solver weight
(plus normal time-decay weighting if the solve enables time decay). Player id `0` is not
given a coefficient, so the known players receive their normal design-matrix entries and
the missing slots are simply unmodeled.

The lineup reconstruction harness is:

```bash
python nba_pipeline/scripts/reconstruct_friend_lineups.py
```

By default it writes
`validation/friend_ingest/raw/BKN_2020_rs_friend_reconstructed_lineups.parquet`
and `validation/friend_ingest/lineup_reconstruction_report.json`. Its default mode is
hybrid: keep friend row `off_players_on` / `def_players_on` snapshots when both sides are
valid five-man sets, and use the substitution stream to repair invalid row snapshots. Use
`--prefer-stream` only for experiments; pure substitution-stream overwrite performed worse
on the BKN 2020 RAPM validation fixture.

## Current Findings

The converted friend schema is highly promising for event-level metric ingest:

- FGA-based metrics match exactly on matched rows for rim, three, and midrange frequency / make surfaces.
- Turnovers and bad-pass turnovers match exactly on matched rows.
- TS, RAPM point diffs, assists, and rebounds have near-perfect matched-row agreement.
- Small validation solves are strongly correlated with official-subset solves.
  The strongest current RAPM path is original friend snapshots with full-weight
  partial-lineup rows:
  - `RAPM` net correlation: about `0.979`
  - `TS` net correlation: about `0.987`
  - `TOV` net correlation: about `0.965`
  - `REB` net correlation: about `0.989`

The remaining official-only event is `game_id=21900889`, `event_num=352`, where official
NBA PBP has a defensive-goaltending violation row between a made Dinwiddie layup and a
same-clock shooting foul. The friend feed has the made layup, foul, and FT, but omits the
goaltending violation row; this changes the repo parser's and-1 possession split. Do not
genericize this repair from the visible `MAKE -> S.FOUL -> FT 1 of 1` pattern, because that
also matches ordinary and-ones.

The remaining friend-only possession rows are zero-value team rebound rows, mostly around
blocked-shot jump-ball/admin sequences. A broad synthetic jump-ball rule for all blocked
shot + team rebound sequences was tested and rejected because it suppressed many official
team-rebound possessions and worsened solver parity.

Lineup parity is the larger remaining solve-level issue: `740` of `14,541` matched RAPM
rows (`5.09%`) have different official vs friend O/D player sets. Official solve outputs
also contain three tiny-exposure players missing from the friend-converted solves:
Malcolm Miller, Ignas Brazdeikis, and Shamorie Ponds. Use
`validation/friend_ingest/diffs/rapm_lineup_mismatches.csv` to inspect those differences.

Full-weight partial-lineup mode on the original friend row snapshots is currently the best
RAPM solve parity experiment. It produced `739` RAPM lineup mismatches on `14,530` matched
rows (`5.09%`), essentially the same mismatch rate as the strict baseline, but improved
RAPM solve net correlation to `0.9786`. This outperformed the hybrid reconstruction output
with strict complete-lineup filtering (`0.969`) and with partial/full-weight rows (`0.973`).

The hybrid lineup reconstruction pass improves row-level RAPM lineup parity but is not yet
a solve-level default:

- Pure substitution-stream overwrite produced `5,266` RAPM lineup mismatches and was rejected.
- Hybrid snapshot-then-stream repair produced `673` RAPM lineup mismatches, fixing `75` of
  the baseline mismatches and introducing `8` new ones.
- The hybrid raw lineup report had `33,720` rows where valid friend snapshots were preferred,
  `6,183` rows repaired by stream fallback, and `187` invalid real non-sub rows remaining.
- Hybrid solve parity was mixed: lineup mismatches improved, but BKN fixture RAPM net
  solve correlation dropped to about `0.969` versus the baseline adapter's about `0.977`.
  Treat the hybrid output as a diagnostic/repair candidate until the remaining high-leverage
  repaired stints are audited.

Concrete conversion differences handled by the adapter:

- The friend schema emits all blocked shots as two rows with the same `actionNumber`:
  the missed shot row plus a separate `block` row. There are `702` block rows and all
  duplicate a 2PT/3PT action number.
- The friend schema emits all steals as separate duplicate-action rows after turnovers:
  there are `1,018` steal rows and all duplicate a turnover action number.
- These auxiliary rows are dropped during conversion because official NBA PBP embeds those
  details on the shot/turnover row; keeping them as standalone rows breaks lag-based
  rebound and possession parsing.
- Friend rows with neutral offensive actions, especially `team=None` shot-clock turnovers,
  need offense side inferred from `off_players_on` against game side player sets.
- Friend substitution rows are usually useful for the repo's foul-to-FT lineup propagation,
  but a small set has out-of-order period clocks. The adapter drops substitution rows whose
  period clock increases relative to the previous event after duplicate-action cleanup.
- A delayed missed-final-FT team rebound sequence can omit an official jump-ball spacer;
  the adapter synthesizes that spacer when a missed final FT is followed by a delayed team
  defensive rebound.

## Conversion Notes

For the BKN 2020 fixture, the adapter infers game home/away sides and player side sets from
the official NBA20 feed. A production pre-2014 path needs equivalent schedule side metadata
and roster/player-side inference from the third-party source or a companion schedule file.
